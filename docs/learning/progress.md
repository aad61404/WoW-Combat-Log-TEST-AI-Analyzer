# 能力驗收與進度

## 如何衡量

工具安裝、讀完章節、AI 完成程式都記在「產出」，不直接計入個人能力。
每個能力分別記錄下列等級，不加總成看似精確的百分比：

| 等級 | 必須提供的證據 |
| --- | --- |
| 未驗收 | 尚未看到學習者的回答或操作，不等於不會 |
| L1 解釋 | 用自己的話追蹤流程，指出假設與不知道的部分 |
| L2 驗證 | 先預測結果，再親自執行、核對業務正確性與輸出 |
| L3 診斷 | 遇到反例能提出至少兩個原因，設計實驗區分，根據證據修正結論 |
| L4 遷移與取捨 | 改變資料量、故障或部署條件後仍能處理，說明成本、副作用與回滾 |

允許查文件與使用 AI；紀錄協助程度（獨立／提示／共同實作／AI 代做）。
AI 代做的結果只證明產出存在；學習者需要在新條件下親自解釋或驗證，才能升級。
沒有證據不推定通過；一次成功也不代表長期熟練。每兩週挑一題換條件重驗。

## 每週只記五件事

1. 我原本預測什麼？
2. 我親自做了什麼，AI 做了什麼？
3. 哪項輸出能支持結論？有哪些替代解釋？
4. 哪個猜測被推翻？下一次如何更快發現？
5. 如果改變一個條件，我會怎麼處理？

不以寫了多少行、學了多少框架、VU 峰值或 prompt 數量評分。

## 階段通過規則

- M0：流程解釋 L1、請求正確性驗證 L2。
- M1：負載模型與業務成功驗證 L2；能說明不能推論什麼。
- M2：交易／冪等性達 L3，以並發反例與修正驗證。
- M3：瓶頸診斷達 L3，至少排除一個替代原因。
- M4：部署恢復達 L3，保留實際恢復資料驗證。
- M5：成本與容量取捨達 L4，區分實測與估算。
- M6：在不同需求下達 L4，說明架構適用與失效條件。

原 roadmap 的 checkbox 保留作待辦，不作能力得分。
